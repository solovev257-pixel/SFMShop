# Стратегия хостинга для проекта SFMShop

## Оценка нагрузки

- Текущая нагрузка: около 10 RPS (запросов в секунду).
- Ожидаемая нагрузка через полгода: около 50 RPS.
- Пиковая нагрузка во время распродаж: около 200 RPS.

Для расчёта средней нагрузки количество запросов за сутки делим на 86400 секунд. Для пиковой нагрузки закладываем запас в 3–5 раз.

Приведённые значения являются предварительной оценкой.

## Выбор хостинга

На начальном этапе выбираем один VPS с конфигурацией 2–4 vCPU и 4–8 ГБ оперативной памяти.

Приложение SFMShop запускаем в Docker, для хранения данных используем управляемую базу данных PostgreSQL (Managed PostgreSQL).

При текущей нагрузке в 10 RPS такой вариант является простым и экономичным решением. Достаточность ресурсов необходимо подтвердить нагрузочным тестированием.

При дальнейшем росте нагрузки можно увеличить ресурсы VPS или добавить дополнительные серверы. Переход на Kubernetes рассматриваем, когда ресурсов одного сервера становится недостаточно и возникает необходимость в отказоустойчивости.

## Стратегия масштабирования

- **Вертикальное масштабирование:** увеличиваем количество vCPU и объём оперативной памяти VPS при нехватке ресурсов.
- **Горизонтальное масштабирование:** добавляем дополнительные серверы с копиями приложения и используем Load Balancer для распределения запросов между ними.
- **Мониторинг:** отслеживаем RPS, время ответа приложения, загрузку процессора и оперативной памяти. Настраиваем уведомления при превышении допустимых значений.
- **Оптимизация:** используем Redis для кэширования часто запрашиваемых данных, RabbitMQ для фонового выполнения длительных задач и индексы PostgreSQL для ускорения поиска данных.

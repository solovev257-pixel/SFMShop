Архитектура баз данных для SFMShop

PostgreSQL — основные данные

Что хранится: пользователи, товары, заказы

Почему PostgreSQL:
данные структурированные и связаны между собой
нужны ACID транзакции (списание денег, создание заказа)
сложные запросы с JOIN

Redis — кэш и сессии

Что хранится: кэш товаров, сессии пользователей, очереди задач

Почему Redis:
данные временные, есть TTL
нужна максимальная скорость (в памяти)
простая структура ключ-значение

MongoDB — логи и аналитика

Что хранится: логи приложения, аналитические события

Почему MongoDB:
разные типы логов имеют разную структуру
гибкая схема без миграций
удобна для аналитических запросов

Поток данных при создании заказа

Пользователь оформляет заказ — запись в PostgreSQL
Кэш товаров в Redis инвалидируется
Событие создания заказа записывается в MongoDB

Минусы гибридной схемы

сложнее поддерживать три разных базы данных
нужно синхронизировать данные между ними
больше компонентов которые могут упасть
выше порог вхождения для новых разработчиков

Стратегия масштабирования БД для проекта SFMShop

Репликация

Когда использовать:
Высокая нагрузка на чтение
Нужна отказоустойчивость

Преимущества:
Отказоустойчивость
Масштабирование чтения
Проще в настройке

Недостатки:
Задержка репликации
Не масштабирует запись

Примеры для SFMShop:
Чтение списка товаров идёт из реплики
Чтение заказов пользователя идёт из реплики
Создание заказа идёт в основную БД

Шардирование

Когда использовать:
Очень большие объемы данных
Нужно масштабировать запись

Преимущества:
Масштабирование записи
Горизонтальное масштабирование

Недостатки:
Сложность в настройке
Сложные JOIN запросы

Примеры для SFMShop:
Шардирование по user_id для заказов
Hash sharding для равномерного распределения

Компромиссы

Eventual Consistency:
Данные в репликах могут быть не синхронны
Приемлемо для чтения каталога
Неприемлемо для списания денег

Рекомендации:
Использовать репликацию для начала
Переходить на шардирование при необходимости

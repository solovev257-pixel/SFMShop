# Почему PostgreSQL для SFMShop?

## Требования проекта
- Хранить пользователей, товары и заказы
- Связи между данными (пользователь → заказы → товары)
- Нельзя создать заказ для несуществующего пользователя
- Нужны сложные запросы

## PostgreSQL 
**Плюсы для SFMShop:**
- Чёткие связи через REFERENCES (user_id → users.id)
- БД сама следит за целостностью данных
- Поддержка сложных запросов с JOIN
- Надёжность — нельзя сломать связи случайно

**Минусы:**
- Строгая структура — сложно менять схему
- Требует проектирования заранее

## MongoDB для SFMShop
**Плюсы:**
- Гибкая структура — легко менять
- Быстрое добавление данных

**Минусы для SFMShop:**
- Нет строгих связей — можно создать заказ без пользователя
- Целостность нужно проверять вручную в коде
- Сложнее делать запросы с объединением таблиц

## Вывод
PostgreSQL — правильный выбор для SFMShop потому что
данные чётко связаны и целостность критически важна.

## Когда MongoDB был бы лучше
- Хранить логи ошибок: {"time": "10:30", "error": "..."}
- Данные без чёткой структуры
- Когда структура часто меняется
